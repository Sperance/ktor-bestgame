# RULES.md - правила ktor-bestgame (сервер)

Дополняет `CLAUDE.md`; при противоречии `CLAUDE.md` главнее. Читай в начале каждой задачи. Раздел «Общее» одинаков с `RULES.md` клиента ExileForge - правь оба.

## Общее (сервер и клиент)

### Игровые инварианты
- Любая сущность с редкостью (предмет, питомец, всё новое) держит дно и потолок модификаторов из `content/rules.json` → `rarities` на каждом пути: ролл, сферы, ремесло, торговец, разведение, старые данные. Если дно удержать нельзя - понижай редкость, пустым не оставляй.
- Ни одного балансного числа в Kotlin: шансы, веса, цены, лимиты, таймеры, коэффициенты - только в `content/*.json` с типизированным чтением (`EngineRules`, теги `tables.json`). Нашёл число в коде при правке - вынеси.
- Всё, что даёт ценность (лут, опыт, золото, предмет, питомец, валюта), роллится детерминированно в `rules/` через `Dice`/seed и подтверждается сервером. Бой считается на клиенте (`core/campaign/Combat.kt`), сервер проверяет правдоподобие лога событий.
- `rules/` - чистый JVM: без Ktor, Mongo, Android, без `kotlin.random.Random` мимо `Dice` и без `System.currentTimeMillis`. Сервер и клиент не дублируют и не «подправляют» его результат.
- Стадия альфа: совместимость со старыми сохранениями не обязательна - при несовместимой схеме база сбрасывается; миграции и ремонт «ради старых данных» не пиши.

### Локализация
- Ни одной строки для игрока в Kotlin - только словари (`ui()`/`loc()` в клиенте, `LocaleKey` на сервере). Исключение: бренд и отладочные экраны.
- Оба словаря (сервер `locale/*.json`, клиент `ui_*.json`) правь сразу на всех языках в одном коммите; `LocalizationTest` и `UiStringsTest` зелёные.
- Новый язык - только полным комплектом: сервер `locale/<lang>.json` + `index.json`, клиент `ui_<lang>.json` + `enum Lang`.
- Новый код ошибки (`funException*`, `RuleViolation`) - с локализацией на всех языках.

### Версии и релиз
- Семвер: `feat` → minor, `fix`/`refactor`/`docs`/`style` → patch, major только по просьбе. Несколько фич в одной задаче - один minor.
- Задача на оба репо: сначала сервер (коммит, пуш), затем в той же задаче клиент закрепляет его - сабмодуль `backend/`, `SERVER_COMMIT`/`SERVER_VERSION` в `Contract.kt`, `API_REVISION` в `Sync.kt`. Пока клиент не закрепил новый сервер, задача не закрыта.
- Коммиты по-английски, Conventional Commits. Комментарии и KDoc по-русски; старые не переписывать.
- Источник правды - код и KDoc. Доки, дублирующие код (контракт API, описание CI), не заводить.
- Перед пушем гоняй только тесты, затронутые изменением: контент/локаль → `LocalizationTest`, `ContentLoadTest`; ролл/сферы → `RulesInvariantsTest`; предмет/стат → `IconsTest`; словарь клиента → `UiStringsTest`. Остальное проверит CI.

### Стиль
- ktlint (`.editorconfig`: `intellij_idea`, без ограничения длины строки) - ворота CI. Перед пушем `ktlintCheck`, форматирование - `ktlintFormat`. Правила в `.editorconfig` не ослаблять без просьбы.

## Сервер

### Версии
- `SERVER_VERSION` (`Constants.kt`) - каждое изменение.
- `API_REVISION` (`Constants.kt`) - только когда клиент обязан перейти на новые маршруты или схему; строка истории в KDoc.
- `RULES_VERSION` (`rules/.../content/Content.kt`) - только когда меняется результат ролла или расчёта: подъём обрывает незаконченные забеги и сбрасывает кэш клиента. Правка текста, иконок и локали его не поднимает. Строка истории в KDoc.
- CHANGELOG не ведётся: история - KDoc у `API_REVISION`/`RULES_VERSION` и коммиты.

### Архитектура
- Новый роут: `RouteRegistrar`/`BaseRoute` в `features/data/<x>/XRoute.kt`, модель и репозиторий рядом, логика в `features/logic/<x>/XService.kt`, регистрация в `RouteRegistry` и Koin (`application/koin/Modules.kt`). Роут без игровой логики, сервис без Ktor.
- Любая мутация героя - внутри `HeroLocks.withLock(heroId)` и `MongoFactory.transactionExecute`. Мутирующий POST поддерживает `Idempotency-Key`.
- Ошибки - только коды через `funException*`/`RuleViolation(code)` с маппингом в `StatusPage.kt`; строковых сообщений в ответах нет.
- Контент валидируется `ContentLoader` на старте; битый контент - падение старта, тихих фоллбэков нет.
- Секреты и настройки - только из окружения через `Constants.kt`; дефолтов для секретов нет; ничего секретного в коде, JSON и workflow.
- Новый предмет - иконка через `scripts/gen_icons.py` (`icons_mono.json`); дерево умений - `scripts/gen_skill_tree.py` и `layout_tree.py`, не руками.

### CI
- `deploy.yml`: `ktlintCheck`, `:rules:ktlintCheck`, `:rules:test` и фильтры `--tests` только по существующим классам; новый критичный серверный тест добавляй в фильтр. Деплой на VPS - только после зелёных проверок.
