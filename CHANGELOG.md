# История изменений · ktor-bestgame

Сервер. Версия — `SERVER_VERSION`, закреплённая клиентом в
`core/.../contract/Contract.kt` вместе с коммитом этой ветки.
Клиент ведёт свой файл: `ExileForge/CHANGELOG.md`.

Новая запись добавляется **сверху**, в день, когда изменения прошли проверки и уехали в ветку.
Коротко: что поменялось и, если что-то чинилось, в чём была причина.

## 0.54.0 — 2026-09-25

Работает с ExileForge 2.61.0. Ревизия API — 7.

- **Тиры в справочнике мира.** У каждого модификатора в `world/world.json` появилось поле
  `tiers`: номер тира и диапазон `[min, max]` на каждый эффект. По ним карточка предмета
  показывает, насколько хорош ролл внутри тира. Отпечаток справочника учитывает и кеш тиров.

## 0.53.0 — 2026-09-25

Работает с ExileForge 2.60.0. Ревизия API — 7.

- **Исправлено: волшебные и редкие предметы без аффиксов.** Число аффиксов теперь задаёт таблица
  редкости для всех предметов, а не только для карт: волшебный 1–2, редкий 4–6
  (`EnumRarity.affixes`). В пул больше не попадают описания без тиров. Причина: такое описание
  при выборе молча съедало место, и предмет выходил пустым. Кроме того, чистка флаконов в 0.51.0
  сняла аффиксы с уже выданных вещей.
- **Переход:** при старте недостающие аффиксы дороллятся на всех копиях, в сумках и на аукционе.
  Лишние аффиксы сверх мест префиксов и суффиксов снимаются.
- **Сферы держат минимум.** Сфера очищения не опускает предмет ниже минимума редкости
  (`CR_025`). Сфера царей дороливает редкий предмет до четырёх аффиксов.
- **Эпической редкости больше нет.** Базы прежних эпических и мифических предметов (88 штук)
  стали редкими, их выданные копии тоже.
- **Мифические предметы** (`mythics.json`, `MYTHICAL`). По одному на каждый из 12 слотов,
  с 2–3 закреплёнными строками, каждая в 2–3 раза сильнее лучшего тира.
  - Роллятся как уникалки: сфера божественности перекатывает значения, а сферы аффиксов к ним
    не применяются.
  - Падают впятеро реже уникалок и только с карт 15-го уровня и выше.

## 0.52.0 — 2026-09-25

Работает с ExileForge 2.59.0. Ревизия API — 7.

- **Новое дерево навыков.** Неровное колесо в духе POE: Scion в центре, шесть классов по кругу.
  У каждого класса четыре ветви с кластерами, по два keystone и гнездо; соседние классы связаны
  мостами. Всего 447 узлов (было 321), у малых узлов по два бонуса, у notable по три-четыре.
  Дерево собирает `scripts/gen_skill_tree.py`, результат детерминирован.
- **Мастерства** (`MASTERY`): центр кластера. Берутся рядом с любым notable кластера, игрок
  выбирает один из трёх вариантов. Мастерство — лист: путь через него не идёт.
- **Атрибутные узлы** (`ATTRIBUTE`): при взятии выбирается +8 к силе, ловкости или интеллекту.
- **API:** у узла дерева появилось поле `options` (варианты бонусов), у взятого узла героя —
  `choice`. `POST /character/skilltree/allocate` принимает `choice`: у мастерства и атрибутного
  узла он обязателен, у остальных запрещён (`ST_018`).
- **Переход бесплатный.** Старые коды узлов исчезли, поэтому при старте у героев остаётся только
  стартовый узел класса, без траты сфер сожаления. Самоцветы из исчезнувших гнёзд возвращаются
  в сумку.

## 0.50.0 — 2026-09-24

## 0.49.0 — 2026-09-24

Работает с ExileForge 2.56.0. Ревизия API — 6 (`API_REVISION`).

- **Кеши справочников.** Неизменяемый снимок с индексом по `_id`: поиск O(1) вместо перебора,
  читатели не ловят гонку с правкой. Производные индексы (по коду, по слоту, тиры модификатора,
  пулы по тегам, граф дерева, таблица уровней) считаются один раз на ревизию. Правки из
  репозиториев доезжают в кеш после коммита транзакции, а не до. Отпечаток кеша не зависит от порядка.
- **Ролл модификаторов.** Тир - два двоичных поиска по накопленным весам; пул аффиксов шаблона
  и пулы сфер/ремесла/добычи собираются один раз на ревизию; выбор аффиксов отсеивает
  кандидатов по ходу, а не фильтрует пул на каждое место. Общий `Random` стал потоковым:
  прежний не был потокобезопасным.
- **Сумка героя - карта `bag {itemId: amount}`** вместо строк `"id:amount"`. Трата сферы -
  один точечный `$inc` с условием на остаток, без чтения и записи документа целиком.
  Полная запись документа идёт кодеком коллекции, а не kotlin-reflect.
- **Лист героя.** Считается один раз на запрос и живёт в памяти по ключу
  `version:inventoryRevision:ревизии справочников`; пересчёт по ходу надевания - только перед
  предметом с требованиями. Поле `unwearable` убрано: клиент выносит вердикт сам из справочника.
  `GET /crafts` читает надетое и лист один раз на все профессии, а не на каждую.
- **Снимок героя.** Версии частей - счётчики (`version` персонажа, `inventoryRevision`
  инвентаря, ревизии справочников), без SHA-256 и повторных чтений: персонаж читается один раз,
  часть кодируется только если у клиента её нет. Инвентарь уходит дельтой из журнала запроса
  (`HeroPart.base` + `{changed, removed}`), когда клиент держит ту версию, с которой команда начала.
- **Инвентарь.** Ревизия героя двигается один раз на транзакцию; профессиональный крафт вставляет
  вещи одним `insertMany` и строит пулы один раз на досчёт; гнездо проверяется запросом по
  `socketCode`, а не чтением всего тайника; разовая починка самоцветов до 0.42.0 убрана; индекс
  `{characterId, equippedSlot}`.
- База пересеивается: формат сумки сменился.

## 0.48.0 — 2026-09-24

Работает с ExileForge 2.55.0. Ревизия API — 5 (`API_REVISION`).

- **Меньше запросов с клиента.** `GET /static/index.json` (публичный) — один манифест на старт:
  версия, ревизия, маршруты и отпечатки словарей, иконок, портретов и справочников. Прежние
  манифесты и `/system/routes` остаются.
- **Справочники одним файлом**: `GET /world/world.json` (для вошедшего) — модификаторы, классы,
  уровни, дерево, шаблоны экипировки, предметы и таблицы листа. Отпечаток пересчитывается после
  правки любого из кешей (`MongoCache.revision`), с `ETag`/`If-None-Match` → 304.
- **Снимок героя**: `GET /api/v1/character/view?characterId` — персонаж, вещи, дерево, сумка и
  верстак одним ответом, у каждой части свой отпечаток, у снимка — `ETag`. Команды героя, кузницы,
  дерева, кампании, ремёсел, рецептов и промокодов отвечают им же в поле `hero` рядом с `data`,
  если клиент прислал заголовок `X-Hero-Parts` (`часть=отпечаток,...` или `none`); в снимок идут
  только части, чьи отпечатки у клиента устарели. Сбой снимка команду не отменяет — поле пустое.

## 0.42.0 — 2026-09-24

  принёс цикл, а сервер досчитывает то же самое.

## 0.39.0 — 2026-09-24

Работает с ExileForge 2.43.0.

- **Пулы — это теги** (`features/logic/pools/Pools.kt`), без реестра и без раскрытых списков:
  запись (модификатор предмета или монстра, шаблон, уникалка) сама несёт `pools` — тег → вес, — а
  источник называет теги, из которых тянет. Вес — по первому тегу источника, в котором запись
  состоит, вес 0 её исключает. Новый пул — новый тег на записях и его имя у источника, без кода.
- **Модификаторы — данными**: `content/modifiers.json` (237 определений с явными таблицами тиров
  PoE) вместо 2146 строк `ModifierSeeder.kt`; `spawnWeight` заменён на `pools`. Пулы слотов,
  локальные пулы базы (`local:<статы>`), влияния (`influence:SHAPER`), порчи (`corruption`) и ручной
  работы (`handcrafted:smith`, `handcrafted:map`) больше не собираются кодом. `pools.json` удалён.
- **Уникалки — данными**: `content/uniques.json` вместо `UniqueEquipmentSeeder` на Kotlin; три списка
  (обычные, боссов, кузнеца) и фильтры `bossUniques`/`smithOnly`, повторённые в дропе, Orb of Chance
  и луте боссов, заменены членством в пулах: `drop`, `unique:world`, `unique:chance`, `unique:smith`,
  `boss:<код босса>`. Уникалка босса падает только с него, потому что ни в каком другом пуле не состоит.
- Шаблон экипировки: `modifierIds` → `modifierPools` (теги аффиксов), `fixedModifierIds` (implicit и
  строки уникалки) и `pools` (членство: `drop`, `smith`, `merchant`, пулы уникалок).
- Источники называют пулы в своих файлах: строка таблицы добычи — `equipmentPools`, карта —
  `modifierPools` монстров, босс и правило `bosses` — `uniquePools`, Vaal Orb и Orb of Chance в
  `currency.json`, кузнец и картограф — четыре пула в `crafting`, торговец — `MerchantRules.POOLS`.
  Модификаторы монстров в `campaign.json` несут `pools` вместо `weight`; клиенту по-прежнему уходит

## 0.21.0 — 2026-09-23

Работает в паре с ExileForge 2.9.0: старый клиент с этим сервером не войдёт.

Безопасность:

- **У сессии есть токен.** Вход по паролю и по устройству теперь `POST` с телом и отвечает
  `{user, token}`; токен ходит в `Authorization: Bearer`, в базе лежит только его SHA-256
  (`authsession`), живёт 30 дней и продлевается при использовании. Добавлены `GET /user/me`,
  `POST /user/logout`; смена пароля — `POST` с телом и гасит остальные сессии. Причина: сервер не
  знал, кто делает запрос, и любой, кто знал адрес, мог действовать от чужого персонажа.
- **Доступ проверяется до маршрута.** `AccessPolicy` — одна таблица: публичное, для вошедшего,
  для администратора. Чужой `userId`/`characterId` отклоняется (`AUTH_004`, `AUTH_005`), без
  токена — `AUTH_001`/`AUTH_002`, не администратор — `AUTH_003`; всё на ru/en/zh. Запись через
  общий CRUD — только администратору, кроме создания и удаления своего персонажа (он всегда
  начинает с первого уровня и пустым); коллекции с чужими данными целиком читает только он.
- **Пароли — PBKDF2** (600 000 итераций); старый SHA-256 проверяется один раз и переписывается
  при входе. `device_id`, пароль и соль больше не меняются через CRUD, `device_id` не отдаётся.
- **Секретов в коде нет.** `ADMIN_PASSWORD`, `TEST_PLAYER_PASSWORD`, `MONGO_URI`, `MONGO_DB`,
  `PORT`, `CORS_HOSTS` берутся из окружения; без пароля администратор не заводится. CORS — только
  перечисленным адресам. Удалены демо-маршруты, JWT и cookie-сессии, которыми никто не пользовался,
  и ключ `/system/shutdown` (теперь `POST` и только администратору).
- Лимит запросов — на клиента (600 в минуту), на вход — 10 в минуту с адреса. Непредвиденная
  ошибка отвечает `SP_500` без текста исключения.

Починено:

- **Счётчик промокода** увеличивается атомарно (`$inc`), а не перезаписью документа: два
  одновременных погашения больше не считаются за одно.
- Журнал запросов читал атрибут времени начала, который никто не ставил, и идентификатор
  cookie-сессии, которой больше нет. Теперь длительность берётся из самого вызова, а вместо
  сессии пишется аккаунт.

Добавлено: `GET /system/version`; версия в `build.gradle.kts` совпадает с `SERVER_VERSION`.
