# История изменений · ktor-bestgame

Сервер. Версия — `SERVER_VERSION`, закреплённая клиентом в
`core/.../contract/Contract.kt` вместе с коммитом этой ветки.
Клиент ведёт свой файл: `ExileForge/CHANGELOG.md`.

Новая запись добавляется **сверху**, в день, когда изменения прошли проверки и уехали в ветку.
Коротко: что поменялось и, если что-то чинилось, в чём была причина.

## 1.30.0 — 2026-09-29

Работает с ExileForge 3.31.0 (ревизия API 22, RULES_VERSION 2).

- Награды забега катятся только на сервере — от постоянного семени наград героя и счётчика: убийства, босс, сундуки, кристаллы,
  порча, клад Бездны, Ваал-зона. `RunReport.rewards` — награда по каждому принятому событию. Фикс: смерть сразу давала новое
  семя, и по известному семени можно было перебирать лут босса и сундуков; пауза `newSeedSeconds` теперь при любом закрытии забега.
- Аукцион: лот живёт 30 дней (`expiresAt`, статус EXPIRED), затем возвращается продавцу в тайник или переполнение, сбор не возвращается;
  отказ, если оплата или покупка не влезут в стопку (AU_015, AU_016) — раньше излишек сгорал; цена выше предела стопки — AU_017;
  сбор считается без переполнения.
- Фикс: сфера Peril нарушала пределы префиксов, суффиксов и потолок аффиксов.
- Фикс: старые предметы чинились только при записи — теперь и при показе героя и лотов; починка исправляет и неверную редкость.
- Фикс: смена гильдии обнуляла гильдейские задания и доли (повторный сбор недельных наград); роспуск гильдии ставит откат вступления.
- Фикс: Ваал-зона переживала забег и давала убивать её монстров снова; SUMMON без золота блокировал весь пакет событий;
  события забега не обновляли задания после полуночи UTC.
- Фикс: производные задания (дерево, уровень, зоны, Атлас) засчитывали прогресс до взятия и откаты — теперь от рекорда и с момента взятия;
  невыполнимые задания больше не выдаются. Неизвестные узлы Атласа удаляются. Титул «Картограф» был недостижим (120 > предела 100) — теперь 100.

## 1.29.0 — 2026-09-29

Работает с ExileForge 3.30.2 (ревизия API 21).

- Отпечаток контента включает `RULES_VERSION` кода правил: незаконченный забег закрывается и при смене одного кода правил (раньше — только контента),
  иначе после такого обновления его убийства отклонялись бы. Поднимать при каждой правке, меняющей исход забега.

## 1.28.1 — 2026-09-29

Работает с ExileForge 3.30.1 (ревизия API 21).

- Фикс идемпотентности: временные сбои базы (BRY_001/BRY_002) и 5xx больше не запоминаются на сутки — ключ освобождается;
  перехват зависшего ключа атомарен (раньше два запроса могли оба исполнить команду); сохранение ответа повторяется;
  отказ записывается ещё под замком героя (дубль получал 409 вместо отказа); повтор отдаётся без устаревшего снимка героя;
  ключ привязан к запросу — чужой запрос с тем же ключом получает 422 IDEM_003.
- Фикс: очистка гильдий ставила `updatedAt` в поясе сервера, а не UTC. CORS пропускает `Idempotency-Key`, `X-Hero-Parts` и отдаёт `Idempotent-Replay`.

## 1.28.0 — 2026-09-29

Работает с ExileForge 3.30.0 (ревизия API 21).

- Замок на вещь: `POST hero/item/lock?itemId&locked`; запертую не продать торговцу (CH_028), не выставить на аукцион (AU_014)

- 12 новых уникальных: по три лука, одноручных меча, одноручных топора и жезла заклинателя на 15/40/65 уровнях.

  и пулы сфер/ремесла/добычи собираются один раз на ревизию; выбор аффиксов отсеивает
  кандидатов по ходу, а не фильтрует пул на каждое место. Общий `Random` стал потоковым:
  прежний не был потокобезопасным.
- **Сумка героя - карта `bag {itemId: amount}`** вместо строк `"id:amount"`. Трата сферы -
  один точечный `$inc` с условием на остаток, без чтения и записи документа целиком.
  Полная запись документа идёт кодеком коллекции, а не kotlin-reflect.
- **Лист героя.** Считается один раз на запрос и живёт в памяти по ключу
  `version:inventoryRevision:ревизии справочников`; пересчёт по ходу надевания - только перед
  предметом с требованиями. Поле `unwearable` убрано: клиент выносит вердикт сам из справочника.
  `GET /crafts` читает надетое и лист один раз на все профессии, а не на каждую.
- **Снимок героя.** Версии частей - счётчики (`version` персонажа, `inventoryRevision`
  инвентаря, ревизии справочников), без SHA-256 и повторных чтений: персонаж читается один раз,
  часть кодируется только если у клиента её нет. Инвентарь уходит дельтой из журнала запроса
  (`HeroPart.base` + `{changed, removed}`), когда клиент держит ту версию, с которой команда начала.
- **Инвентарь.** Ревизия героя двигается один раз на транзакцию; профессиональный крафт вставляет
  вещи одним `insertMany` и строит пулы один раз на досчёт; гнездо проверяется запросом по
  `socketCode`, а не чтением всего тайника; разовая починка самоцветов до 0.42.0 убрана; индекс
  `{characterId, equippedSlot}`.
- База пересеивается: формат сумки сменился.

## 0.21.0 — 2026-09-23

Работает в паре с ExileForge 2.9.0: старый клиент с этим сервером не войдёт.

Безопасность:

- **У сессии есть токен.** Вход по паролю и по устройству теперь `POST` с телом и отвечает
  `{user, token}`; токен ходит в `Authorization: Bearer`, в базе лежит только его SHA-256
  (`authsession`), живёт 30 дней и продлевается при использовании. Добавлены `GET /user/me`,
  `POST /user/logout`; смена пароля — `POST` с телом и гасит остальные сессии. Причина: сервер не
  знал, кто делает запрос, и любой, кто знал адрес, мог действовать от чужого персонажа.
- **Доступ проверяется до маршрута.** `AccessPolicy` — одна таблица: публичное, для вошедшего,
  для администратора. Чужой `userId`/`characterId` отклоняется (`AUTH_004`, `AUTH_005`), без
  токена — `AUTH_001`/`AUTH_002`, не администратор — `AUTH_003`; всё на ru/en/zh. Запись через
  общий CRUD — только администратору, кроме создания и удаления своего персонажа (он всегда
  начинает с первого уровня и пустым); коллекции с чужими данными целиком читает только он.
- **Пароли — PBKDF2** (600 000 итераций); старый SHA-256 проверяется один раз и переписывается
  при входе. `device_id`, пароль и соль больше не меняются через CRUD, `device_id` не отдаётся.
- **Секретов в коде нет.** `ADMIN_PASSWORD`, `TEST_PLAYER_PASSWORD`, `MONGO_URI`, `MONGO_DB`,
  `PORT`, `CORS_HOSTS` берутся из окружения; без пароля администратор не заводится. CORS — только
  перечисленным адресам. Удалены демо-маршруты, JWT и cookie-сессии, которыми никто не пользовался,
  и ключ `/system/shutdown` (теперь `POST` и только администратору).
- Лимит запросов — на клиента (600 в минуту), на вход — 10 в минуту с адреса. Непредвиденная
  ошибка отвечает `SP_500` без текста исключения.

Починено:

- **Счётчик промокода** увеличивается атомарно (`$inc`), а не перезаписью документа: два
  одновременных погашения больше не считаются за одно.
- Журнал запросов читал атрибут времени начала, который никто не ставил, и идентификатор
  cookie-сессии, которой больше нет. Теперь длительность берётся из самого вызова, а вместо
  сессии пишется аккаунт.

Добавлено: `GET /system/version`; версия в `build.gradle.kts` совпадает с `SERVER_VERSION`.
