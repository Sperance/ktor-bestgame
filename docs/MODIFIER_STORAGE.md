# Определения модификаторов в MongoDB

Каждый модификатор и каждая его версия — отдельный документ коллекции
`ModifierDefinition`. Один большой документ со всеми модификаторами не используется:
это мешало бы независимым изменениям и упиралось в лимит размера BSON.

## Связи

- Определение: `id`, `revision`, `enabled`, правила/диапазоны/эффекты.
- Шаблон Equipment: `modifierDefinitionRefs` и `stockModifierDefinitionRefs` —
  массивы `{definitionId, revision}`. Встроенные определения больше не принимаются.
- Выпавший Modifier: `definitionId`, `definitionRevision`, `values`, `tier`, `source`, `tags`.
- Выпавший PoeRoll: `id`, `revision`, `values`, `fractured`.
- У старых записей без номера версии подразумевается версия 1.

Уникальный индекс `(id, revision)` предотвращает дубли при конкурентной публикации.
API не перезаписывает и не удаляет исторические версии. Публикация с `enabled=false`
отключает модификатор в новом пуле выпадения, но сохраняет возможность читать и крафтить
существующие предметы по закреплённой версии. Divine и Blessed используют исходную
версию диапазона. Chaos/Exalted выбирают новые свойства из актуального включённого пула.

Для PoE источником правил служит `poe` внутри документа определения. При публикации сервер
вычисляет из него тип, диапазоны, теги и поддерживаемые эффекты; их противоречивые копии
из запроса не сохраняются. Для собственных
модификаторов используются `tiers`, `effects`, `conditions` и остальные типизированные
поля. Добавление нового ID и числовых правил не требует пересборки; совершенно новая
боевая механика по-прежнему требует реализации обработчика эффекта.

## Чтение и публикация

`GET /api/v1/poe/modifier-definitions?page=0&size=50&q=life` — поиск всех определений, включая пользовательские.
`GET /api/v1/poe/modifier-definition?id=Strength1` — последняя версия.
`GET /api/v1/poe/modifier-definition?id=Strength1&revision=1` — конкретная версия.
`GET /api/v1/poe/catalog?type=modifiers` читает актуальные PoE-определения из MongoDB.

Администратор публикует определение через:

```http
POST /api/v1/poe/modifier-definitions
Authorization: Bearer <admin-token>
Content-Type: application/json
```

```json
{
  "expectedRevision": 0,
  "definition": {
    "id": "custom_life",
    "name": "Дополнительное здоровье",
    "source": "PREFIX",
    "affixType": "PREFIX",
    "tiers": [{"tier": 1, "minItemLevel": 1, "weight": 100, "values": [{"min": 5, "max": 15}]}],
    "effects": [{"type": "stat", "stat": "maximum_life", "operation": "FLAT", "value": {"type": "modifier_value", "index": 0}}]
  }
}
```

`expectedRevision=0` создаёт новый ID. Для изменения отправьте полное определение и
последнюю прочитанную версию. Сервер сам назначает следующую `revision` и `_id`.
Полученную ссылку можно добавить в `Equipment.modifierDefinitionRefs`.
Для изменения PoE-модификатора получите существующее определение, измените `poe`
и отправьте его с ожидаемой версией. Прямая правка Mongo-документов обходит защиту версий
и не является поддерживаемым способом изменения каталога.

Шаблоны закрепляют версии stock-модификаторов: чтобы изменить implicit для будущей
выдачи этого шаблона, обновите соответствующую ссылку. PoE-пул случайных affix-модификаторов
выбирается по тегам и весам среди последних включённых версий в MongoDB.

## Снимки и миграция

`MongoModifierCatalog` читает определения пакетно и сохраняет неизменяемый снимок в памяти.
Одна операция крафта использует один снимок; запроса MongoDB на каждый модификатор нет.
После публикации локальный кэш сбрасывается сразу; другие процессы обновятся в течение
пяти секунд. Если предмет ссылается на ещё не загруженную версию, обновление выполняется
сразу. При пустой/неполной коллекции операция завершается ошибкой, без скрытой подстановки
встроенного JSON. Файлы RePoE используются только для первоначального наполнения;
каталог базовых предметов пока остаётся в ресурсе сборки.

Seeder сначала создаёт отсутствующие определения, затем запускает идемпотентную
`ModifierReferenceMigration` и создаёт новые шаблоны со ссылками. Каждая миграция шаблона
и его старых экземпляров проходит одной транзакцией. Значения и UUID сохраняются.
Если одноимённое встроенное определение отличается от общего, оно сохраняется под
`legacy/<equipmentId>/<modifierId>`, а ссылки соответствующих старых экземпляров
переносятся на этот ID. Старые исторические версии не удаляются.

Запускайте миграцию при старте до приёма запросов. Существующие ограничения покрытия
PoE из [POE.md](POE.md) сохраняются.
